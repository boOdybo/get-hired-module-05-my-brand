# GET HIRED — Reference Analysis of Modules 01–04

## Purpose
This note records the design and instructional conventions identified in the four supplied reference packages. Module 05 was rebuilt against these conventions. Modules 01–04 were not modified.

## 1. What each reference contributes

| Reference | Observable structure | Reusable design / teaching convention |
|---|---|---|
| Module 01 — WHO AM I? | 27 slides; foundation concepts, a continuing fictional case, prompt comparison, practical challenge, knowledge check and student reference | Strong opening, concept-to-application progression, visible distinction between input, AI output and human review, copyable prompts, notes panel, index, fullscreen and keyboard navigation |
| Module 02 — MY COMMUNICATION FOUNDATION | 25 slides; one message is improved throughout the lesson; Grammarly and ChatGPT are compared against the same task | A single worked example carried through the lesson, before/after comparison, tool roles explained separately, learner practice and critical review of AI suggestions |
| Module 03 — MY STORY | 41 slides; Presentation / Study / Trainer modes; progressive STAR and prompt-engineering sequence; guided and independent practice | Mature three-mode experience, one main teaching purpose per slide, exact source prompt preservation, practice scaffolding, copyable prompts and a searchable overview |
| Module 04 — MY NETWORK | 48 slides; Presentation / Study / Trainer modes; official session map; interactive prompt builder and quiz; full support-document set | Mature responsive shell, clear session boundaries, outcomes, visual models, live-demo sequence, learner workspace, peer review, track-specific deliverables and documented QA |

## 2. Stable conventions across the four modules

### Language
- Arabic is the primary teaching language.
- English tool names, technical terms, source prompts and example outputs remain in English where useful.
- English prompt and example blocks use left-to-right direction; Arabic explanation uses right-to-left direction.
- A source prompt is preserved verbatim and then explained, not silently rewritten.

### Instructional sequence
The references do not simply convert curriculum bullets into slide titles. They build a learning path:
1. Opening and context.
2. Session boundaries and expected outputs.
3. Learning outcomes.
4. Concept explanation and visual model.
5. Worked example or continuing case.
6. Tool demonstration.
7. Guided practice.
8. Independent learner practice.
9. Feedback / peer review.
10. Knowledge check, deliverables and close.

Not every module uses exactly the same number of slides or the same ordering, but this teaching logic recurs.

### Visual language
- Light, high-contrast presentation background.
- Deep navy / teal / blue accents and white content panels.
- Large Arabic headings and readable body text.
- Cards, comparisons, workflows and diagrams serve a teaching purpose.
- Slide numbers, section labels and progress indicator orient the learner.
- Dense content remains scrollable within the slide rather than being clipped off-screen.
- Responsive breakpoints are part of the deck, not an afterthought.

### Navigation and interaction
The first two modules use an earlier interaction shell. Modules 03 and 04 establish the more mature pattern:
- Presentation mode for projection.
- Study mode for expanded student explanations.
- Trainer mode for facilitation notes.
- Previous / next controls and keyboard navigation.
- Slide counter and progress bar.
- Searchable slide overview.
- Fullscreen control.
- Copyable prompts.
- Relevant interactive activities, prompt builders or quiz feedback.

Module 05 adopts the mature three-mode shell from Modules 03–04 while retaining the instructional conventions visible in all four references.

### Source and instructional boundaries
- Exact source content is distinguished from trainer-designed explanation and enrichment.
- Fictional examples are labelled as fictional.
- A sample output is not described as a live tool result unless it was actually generated during the demonstration.
- Outputs belonging to other programme tracks are not reassigned to AI Tools.
- Where the source itself is ambiguous, the ambiguity is disclosed rather than silently resolved.

### Supporting documents
The more complete later packages establish a useful support set:
- Source Mapping & Coverage.
- Trainer Guide.
- Student Workbook.
- Activity Brief.
- Slide Storyboard.
- QA Report.
- README.

## 3. Module 05 implementation decisions

- Use the Module 04 shell and interaction model, not the different outer-card shell in the previous Module 05 export.
- Preserve the 12:00–13:30 official session window.
- Include a trainer-designed 90-minute pacing suggestion, explicitly labelled as a suggestion rather than source timing.
- Preserve the seven CV fields exactly as listed in the reviewed source.
- Preserve the source's exact three-sentence CV summary prompt.
- Preserve the source's CV Sprint sequence: ChatGPT → Grammarly → Canva.
- Preserve the exact ten-item peer-review checklist.
- Separate the AI Tools CV output from the Personal Brand Statement and Cover Letter outputs belonging to other tracks.
- Disclose the source mismatch between seven CV fields and five AI prompts. The five-card grouping in the deck is explicitly a trainer proposal requiring programme-owner approval.
- Mark additional prompt templates, the local prompt builder, the take-home task, and the Maryam case as trainer-designed or fictional where appropriate.

## 4. Responsive and functional standard applied

The rebuilt deck was tested at:
- 1920 × 1080
- 1366 × 768
- 1280 × 720
- 768 × 1024
- 390 × 844
- 360 × 800

The acceptance target is:
- No horizontal overflow at document or slide level.
- Content-heavy slides scroll vertically inside their own slide.
- The top navigation and bottom controls remain available.
- Presentation / Study / Trainer modes work.
- Navigation, overview search, prompt builder, peer checklist and quiz feedback work.
- No JavaScript runtime errors in the tested workflows.

This is a functional browser test, not a guarantee of identical rendering on every device, browser, projector or live external tool account.


## Additional instructional rule adopted in the Module 05 revision
- Introduce one fictional learner and case file at the beginning, immediately after the cover.
- Carry the same facts through every demonstration; do not switch examples or change candidate details.
- For each CV section, explain the purpose, identify the evidence, demonstrate the writing step, and then show the exact finished section as it would appear in the CV.
- After all sections, show the assembled CV and the same CV after Canva formatting.
- Increase body typography for projector viewing; preserve mobile responsiveness through vertical scrolling rather than shrinking text or clipping content.
- Unknown facts remain placeholders or are omitted. No institution, date, contact information, employer, achievement, metric or certificate is invented.
- Do not add minute-by-minute pacing maps to the student-facing deck.
